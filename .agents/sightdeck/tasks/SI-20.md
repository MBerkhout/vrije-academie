# Scroll 404 pages to the top

## Goal

Navigating to a missing page must show the 404 heading, not the leftover scroll position from the previous (usually longer) page.

## Cause

Next.js App Router keeps the current scroll offset when `notFound()` replaces the page. 404 views are short, so the heading is often above the viewport.

## Approach

Mount a client `ScrollToTopOnMount` on every 404 view (`NotFoundView` and the PDP not-found) and on `ErrorView` (500). Use `useLayoutEffect` plus a short retry so Next.js scroll restoration cannot push the viewport back down.

Do not add a global pathname scroll-to-top; listing return (`ListingReturnScroll`) depends on restoring a card position.
