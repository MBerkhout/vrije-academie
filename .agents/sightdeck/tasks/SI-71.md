# Why Wandeling Vesting Bourtange shows lezing badge

Staging: https://v2.vrijeacademie.nl/ons-aanbod/wandeling-vesting-bourtange

Same product as SI-10. Confirmed again on local Medusa `GET /store/events/wandeling-vesting-bourtange`:

- `product_type` = **Wandeling** (Salesforce developer name, used by Soort activiteit)
- `record_type` = **lezing** (EventGroup)

## Why

Salesforce `Productgroup_Record_Type_Developer_Name__c` is `Wandeling`. Import writes that into two places:

1. Medusa product type via `productTypeValueFromSalesforce()` — keeps `Wandeling`.
2. EventGroup `record_type` via `mapSalesforceRecordType()` — only knows `collegereeks` / `lezing` / `excursie` / `studiedag` / `vathuis`. Anything else, including `Wandeling`, falls through to `"lezing"`.

`PdpHeader` renders `event.record_type` as the extra chip, so the PDP shows **lezing**. Categories Architectuur / Geschiedenis are unrelated.

## Fix if wanted

Show `product_type` on the PDP (already `Wandeling`), or extend `RECORD_TYPES` so Wandeling is a first-class EventGroup type. The latter needs a DB check constraint change and a re-import.
