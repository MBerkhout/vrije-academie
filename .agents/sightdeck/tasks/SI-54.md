# Diagnose VA Thuis Audience Player preview

## Goal

Find why the Audience Player preview on https://v2.vrijeacademie.nl/va-thuis/art-nouveau shows "Deze preview is momenteel niet beschikbaar." and what must be done to make it work.

## Memory

- Modal shows that copy when `playback` is null (`PdpEpisodePreviewModal`).
- Frontend fetches `GET /store/events/:handle/episodes/:episodeKey/preview-playback`.
- First episode of chapter 1 is marked `preview_available`.
- Playback uses embed-player SDK + OAuth token via `AUDIENCE_PLAYER_PREVIEW_EMAIL`.

## Resolution / Ergebnis

The storefront player is wired correctly. Staging Medusa has no Audience Player OAuth credentials, so the preview API fails and the modal shows the generic unavailable copy.

**Evidence (2026-09-21):**

- PDP episode 1 is previewable: `preview_available: true`, `audience_article_id: 339`, `audience_asset_id: 200`, `project_id: 14`.
- Browser fetch: `GET https://medusa.vrijeacademie.nl/store/events/art-nouveau/episodes/1-1/preview-playback` → **500** `{ "type": "unexpected_state", "message": "Audience Player OAuth credentials are not configured" }`.
- Frontend treats any non-OK as `playback: null` → “Deze preview is momenteel niet beschikbaar.”
- Local `medusa/.env` already has `AUDIENCE_PLAYER_CLIENT_ID` / `AUDIENCE_PLAYER_CLIENT_SECRET`. POC `node scripts/test-audience-player-playback.mjs --email=vathuis-preview@vrijeacademie.nl --article=339 --asset=200` succeeds (user 14057, HLS+DASH entitlements, duration 91s).

**To make it work on v2:** on the Medusa server, add those two vars to `~/app/medusa/.env` (optional: `AUDIENCE_PLAYER_PROJECT_ID=14`, `AUDIENCE_PLAYER_PREVIEW_EMAIL=vathuis-preview@vrijeacademie.nl`), then `pm2 startOrReload ecosystem.config.cjs`. Smoke-test the preview-playback URL with the publishable API key — it should return `{ playback: { token, articleId, assetId, … } }`. Purchased playback uses the same credentials.

No code change required for the player itself.
