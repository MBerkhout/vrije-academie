# Manual page cache clear in Sanity

## Goal

Editors can bust a CMS page's Next.js ISR cache from Sanity Studio, from the document ⋯ menu, without publishing or waiting 60 seconds.

## Why

Publishing already hits `POST /api/revalidate/sanity` via webhook. When that fails, or the page still looks stale, there is no manual fallback besides waiting or redeploying.

## Approach

1. Add a `Clear page cache` document action on `page` only, in `group: paneActions` (the pane ⋯ menu, not the Publish bar).
2. Studio POSTs `{ _type, slug }` to the storefront with a Bearer secret. Use a **separate** secret from the webhook HMAC (`SANITY_STUDIO_REVALIDATE_SECRET`) so the HMAC key is not bundled into Studio JS.
3. New `POST /api/revalidate/studio` with CORS for hosted Studio (`*.sanity.studio`) and local `localhost:3333`. Manual clear also revalidates VA Thuis paths (webhook still skips those as force-dynamic).
4. Confirm dialog before the request; toast on success/failure.

## Out of scope

- Site-wide chrome bust from General Settings (still webhook-only).
- Medusa Redis listing cache.
- Forging or replacing the publish webhook.
