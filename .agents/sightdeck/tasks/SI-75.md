# Which Salesforce record types are missing from EventGroup

## Should Wandeling be added to `RECORD_TYPES`?

No. `EventGroup.record_type` is a coarse 5-value enum (`collegereeks | lezing | excursie | studiedag | vathuis`). Salesforce `Productgroup_Record_Type_Developer_Name__c` is already stored as Medusa `product.type` (`product_type`). The storefront Soort activiteit filter and `/ons-aanbod/wandeling` landings already use that field. The Bourtange **lezing** chip is `PdpHeader` rendering `record_type` instead of `product_type`.

SI-26 / General Settings already say the PDP badge stays the singular Salesforce name (Reis, Wandeling, …).

Adding only `wandeling` would still leave Reis, Workshop, Rondleiding, Live_College, etc. labelled lezing, and would duplicate `/ons-aanbod/wandeling` with `?record_type=wandeling`. It also needs a DB check-constraint migration and a re-import.

## If keeping the coarse enum

Optional aliases only (not new enum values): `Live_Collegereeks` → collegereeks, `Excursies_Collegereeks` → excursie, `Online_Studiedag` → studiedag. Live_College is already correctly a lezing.

## If the PDP badge should say Wandeling

Use `product_type` (and `plpProductTypeHref` for reis/studiedag/wandeling/workshop). Do not extend `RECORD_TYPES`.
